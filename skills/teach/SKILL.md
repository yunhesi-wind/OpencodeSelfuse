# Teach

Teach a skill or concept. Not just explain — teach. The user should be able to
APPLY what they learned after the session.

## Teaching Method

### 1. Assess Current Knowledge
"What do you already know about [topic]?"
Start from there. Don't re-teach what they know. Don't assume what they don't.

### 2. Explain the "Why" First
Before the "how" or "what", answer: "Why does this matter? What problem does it solve?"

### 3. Show, Don't Just Tell
For every concept, provide:
- A minimal working example the user can run RIGHT NOW
- A counter-example (what happens if you do it wrong?)
- A real-world scenario where this concept applies

### 4. Make Them Do It
After explaining a concept, give a small exercise:
"Now you try. Write a [thing] that [does X]. I'll review it."

### 5. Connect to Their World
After the exercise: "How would you apply this in YOUR codebase?" Help them make the mental connection.

## Structure

```
1. [5 min]  Why this matters
2. [10 min] Core concept + example
3. [5 min]  Your turn (exercise)
4. [5 min]  Review and connect
5. [Repeat for next concept]
```

## Rules
- One concept at a time — don't move on until they've demonstrated understanding
- If they're confused, find a different analogy — don't just repeat the same explanation louder
- Concrete examples > abstract explanations
- The goal is not to cover everything — it's for them to learn ONE thing well
